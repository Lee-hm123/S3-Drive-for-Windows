# ☁️ S3 Drive for Windows

> 🟦 将任意 **S3 / S3 兼容对象存储**挂载为 Windows 资源管理器盘符。  
> 🟩 支持多桶、按需读取、VFS 缓存、托盘状态、自动恢复、安全退出与操作审计。

| 🟢 已连接 | 🟡 正在同步 | 🔴 错误 | ⚫ 已停止 |
| :---: | :---: | :---: | :---: |
| 可正常使用 | 等待或正在上传 | 查看状态与日志 | 已安全卸载 |

## ✨ 功能概览

- 🪣 **多桶挂载**：每个桶使用独立盘符、RC 端口、缓存和日志。
- 📖 **按需读取**：打开文件时才读取所需数据，不会提前下载整个桶。
- 💾 **VFS `full` 缓存**：支持随机读写、大文件、编辑保存和延迟上传。
- 🔄 **目录刷新**：定时刷新目录元数据，资源管理器按 `F5` 可立即重新列举。
- 🧭 **托盘状态**：查看连接、上传队列、失败数、日志位置并执行安全退出。
- 🛡️ **自动恢复**：管理器或审计器意外退出后，由守护器静默重启。
- 🧾 **操作审计**：记录本地创建、重命名和删除事件。
- 🔔 **错误反馈**：挂载、配置或运行异常可通过托盘状态和日志反馈。

## 🏗️ 工作架构

```text
🖥️ Windows 资源管理器
          │
          │ 浏览 / 打开 / 保存 / 重命名 / 删除
          ▼
💽 X:、Y: 等云盘盘符 ─────────────── 🧾 操作审计器
          │                                  │
          │                                  └─ 记录本地文件操作
          ▼
🔧 rclone mount + WinFsp
          │
          ├─ 💾 VFS 本地缓存与上传队列
          ├─ 📊 RC 本机状态接口
          └─ 🔐 HTTPS / S3 API
          ▼
☁️ S3 对象存储桶

🧭 托盘管理器
          ├─ 挂载与自动恢复
          ├─ 查询队列与错误
          ├─ 刷新目录元数据
          └─ 安全退出
```

> 🟦 **数据路径**：资源管理器 → 盘符 → rclone / WinFsp → S3。  
> 🟪 **审计路径**：资源管理器操作 → 审计器 → 本地 JSONL 日志。  
> 🟧 **控制路径**：托盘管理器 → 本机 RC 接口 → 状态查询与安全退出。

## ⚙️ 后台进程

| 进程 | 职责 | 是否显示窗口 |
| --- | --- | :---: |
| `rclone.exe` | 连接 S3、提供盘符、处理缓存、上传和下载 | 否 |
| `wscript.exe`（托盘守护） | 静默启动并守护托盘管理器 | 否 |
| `powershell.exe`（管理器） | 托盘菜单、状态查询、目录刷新和自动恢复 | 否 |
| `wscript.exe`（审计守护） | 静默启动并守护审计器 | 否 |
| `powershell.exe`（审计器） | 监听盘符中的创建、重命名和删除 | 否 |

管理器和审计器使用独立进程：审计器退出不会直接中断 rclone 传输；管理器退出时，已经运行的 rclone 通常仍会继续挂载。但管理器停止期间将失去托盘状态和自动恢复能力。

### 🖥️ 高 DPI 显示

托盘管理器在加载 Windows 窗体前启用 Per-Monitor V2 DPI 感知，避免在 125%、150% 或多显示器缩放环境中被 Windows 位图放大。后台进程通过 `wscript.exe` 和隐藏窗口方式启动，不需要一直保留 CMD 或 PowerShell 黑框。

## 🧩 运行环境

### 🔌 必需组件

| 组件 | 用途 | 是否需要常开 |
| --- | --- | :---: |
| Windows 10 / 11（64 位） | 资源管理器、系统托盘、任务计划程序 | ✅ |
| [WinFsp](https://winfsp.dev/) | 提供 Windows 盘符所需的文件系统接口 | 系统驱动 |
| rclone | S3 连接、挂载、缓存、上传下载和 RC 接口 | 挂载期间 |
| Windows PowerShell 5.1 | 运行管理器和审计器 | 后台静默 |
| Windows Script Host | 无黑框启动并守护 PowerShell | 后台静默 |

### 🌐 使用前提

- 电脑可以通过 HTTPS 访问你的 S3 Endpoint。
- 已获得服务商提供的 Endpoint、Region 和 S3 访问凭据。
- 凭据拥有目标桶所需的列目录、读取、写入或删除权限。
- 每个启用桶都有未占用的盘符和唯一 RC 端口。
- 本机磁盘为 VFS 缓存预留了足够空间。

> [!NOTE]
> 本工具不依赖 Python、Node.js、Docker、数据库或浏览器扩展。

## 🚀 快速开始

### 1️⃣ 安装 WinFsp

安装 WinFsp 后通常无需手动打开。rclone 挂载时会自动使用其文件系统驱动。

### 2️⃣ 准备 rclone

确认目录结构为：

```text
rclone\rclone.exe
```

### 3️⃣ 创建 S3 remote

在本目录打开 PowerShell，运行：

```powershell
.\rclone\rclone.exe config
```

选择 `n` 新建 remote，并按服务商文档填写 Provider、Endpoint、Region、Access Key ID 和 Secret Access Key。remote 名称可自定义，例如 `s3remote`。

> [!CAUTION]
> 不要把 Access Key、Secret Key、会话 Token 或签名 URL 写进 `配置.json`、脚本、README、Issue 或日志截图。

### 4️⃣ 编辑挂载配置

打开 `配置.json`，将示例 remote、桶名、盘符和端口改成自己的配置，再把 `enabled` 设置为 `true`。

### 5️⃣ 启动并检查

1. 双击 `启动S3云盘.vbs`。
2. 等待数秒，在资源管理器确认盘符出现。
3. 双击 `查看状态.cmd`，确认状态为 `Connected`。

## 🪣 多桶配置

### 🧩 完整示例

```json
{
  "version": 1,
  "buckets": [
    {
      "id": "example-bucket",
      "displayName": "Example Bucket",
      "remote": "s3remote:example-bucket",
      "drive": "X:",
      "rcPort": 5572,
      "enabled": false,
      "vfsCacheMode": "full",
      "vfsWriteBack": "5s",
      "vfsCacheMaxAge": "7d",
      "vfsCachePollInterval": "1m",
      "quotaTotalBytes": 0
    }
  ]
}
```

### 🔑 每个键的作用

| 键 | 作用 | 规则与建议 |
| --- | --- | --- |
| `id` | 本机缓存、日志和状态目录的稳定标识 | 仅用字母、数字、`-`、`_`；每桶唯一 |
| `displayName` | 资源管理器和托盘中显示的盘名 | 可使用中文和空格 |
| `remote` | rclone remote 与桶路径 | 格式：`remoteName:bucket-name` |
| `drive` | Windows 盘符 | 格式如 `X:`；每桶唯一且不能已被占用 |
| `rcPort` | 本机状态与安全退出接口端口 | 建议从 `5572` 递增；每桶唯一 |
| `enabled` | 是否启用该桶 | 配好前保持 `false`，确认后改为 `true` |
| `vfsCacheMode` | VFS 缓存模式 | Windows 日常使用建议保持 `full` |
| `vfsWriteBack` | 文件关闭后等待多久开始上传 | 默认 `5s`，可减少重复上传 |
| `vfsCacheMaxAge` | 已上传缓存文件的最长保留时间 | 示例 `24h`、`7d` |
| `vfsCachePollInterval` | 检查缓存队列的间隔 | 建议 `1m` |
| `quotaTotalBytes` | 资源管理器显示的固定总容量 | 单位为字节；`0` 表示未知 |

> [!WARNING]
> JSON 不支持注释、单引号和末尾多余逗号。多个已启用桶不能共用 `id`、盘符或 RC 端口。

## 🖱️ 日常使用

| 操作 | 入口 | 结果 |
| --- | --- | --- |
| ▶️ 启动 | 双击 `启动S3云盘.vbs` | 静默启动管理器并挂载所有启用桶 |
| 📂 打开云盘 | 在资源管理器打开对应盘符 | 像普通磁盘一样浏览和读写 |

> 🔴 不要强制结束 `rclone.exe`，否则可能中断正在上传的数据。

## 🔄 刷新与同步

### 🔃 查看服务器最新目录

- `--dir-cache-time 0s`：目录重新枚举时向服务器请求最新内容。
- 托盘管理器每 5 分钟调用 `vfs/refresh` 刷新目录元数据。
- 已打开的资源管理器窗口不一定自动重绘；需要立即查看远端变化时，请按 `F5` 或重新进入目录。

### 💾 `VFS full` 与延迟写回

```text
保存文件 → 写入本地缓存 → 文件关闭 → 等待约 5 秒 → 上传 S3 → 队列归零
```

资源管理器显示“复制完成”只代表数据已经交给 VFS，不代表云端上传已经完成。

### 📡 状态含义

| 状态 | 含义 | 建议操作 |
| :---: | --- | --- |
| 🟢 `Connected` | 已连接，当前没有待上传内容 | 可正常使用 |
| 🟡 `Syncing` | 文件正在等待或正在上传 | 保持网络和程序运行 |
| 🔴 `Error` | rclone 报告传输错误 | 查看状态和 `rclone.log` |
| 🔴 `Disconnected` | 盘符或连接已断开 | 等待自动恢复或手动启动 |
| ⚫ `Stopped` | 已执行安全退出 | 需要时重新启动 |

只有 `Queued = 0`、`Uploading = 0`、`Failed = 0` 且 `Errors = 0` 时，才应认为当前上传队列已经完成且未检测到错误。

## 🛡️ 后台守护

### 🔗 守护链路

```text
🟦 Windows 任务计划程序
          │
          ├── 🟩 托盘守护.vbs
          │        └── 🧭 S3Drive管理器.ps1
          │                 └── 🔧 rclone.exe
          │
          └── 🟪 审计守护.vbs
                   └── 🧾 S3Drive审计.ps1
```

如需登录后自动挂载，在 Windows“任务计划程序”中创建：

| 任务名示例 | 程序 | 参数 |
| --- | --- | --- |
| `S3 Drive Monitor` | `C:\Windows\System32\wscript.exe` | `"完整路径\托盘守护.vbs"` |
| `S3 Drive Operation Audit` | `C:\Windows\System32\wscript.exe` | `"完整路径\审计守护.vbs"` |

两个任务都设置为“用户登录时”触发，并选择“仅当用户登录时运行”。守护脚本会隐藏命令行窗口，并在对应 PowerShell 意外退出后约 5 秒重新启动。

### 🚨 强制结束不同进程的影响

| 被结束的进程 | 直接影响 | 自动恢复方式 |
| --- | --- | --- |
| `rclone.exe` | 盘符断开，正在上传的数据可能中断 | 管理器检测到断开后尝试重新挂载 |
| 管理器 `powershell.exe` | 托盘与状态轮询暂时消失，已有盘符通常继续工作 | `托盘守护.vbs` 约 5 秒后重新启动管理器 |
| 审计器 `powershell.exe` | 操作日志短暂缺失，不影响 rclone 传输 | `审计守护.vbs` 约 5 秒后重新启动审计器 |
| `wscript.exe` | 对应 PowerShell 失去第一层守护 | 由任务计划程序的失败重启策略或手动启动恢复 |

> [!WARNING]
> 强制结束 `rclone.exe` 不是安全退出。正确做法是先确认上传队列为空，再使用托盘菜单或 `安全退出.cmd`，由 RC 的 `core/quit` 正常结束。

### 🔁 自动恢复边界

- 网络短暂中断时，rclone 自身会按重试参数继续请求。
- 盘符消失且未被标记为安全停止时，管理器会重新挂载。
- 配置文件无效、盘符被其他设备占用、凭据失效或 WinFsp 缺失时，自动重试无法替代人工修复。
- 执行“退出程序”后会留下退出标记，防止守护器立刻将程序重新拉起；再次手动启动会清除该标记。

> [!TIP]
> 移动整个工具文件夹后，只需更新计划任务的两个参数路径；不要单独移动其中单个文件。

## 🗂️ 缓存与日志

运行时数据位于当前用户目录，不在发布包内：

```text
%LOCALAPPDATA%\S3Drive\buckets\<id>\
├─ cache\                         💾 VFS 本地缓存
├─ state\paused                  ⚫ 安全退出标记
└─ logs\
   ├─ manager.log                🧭 挂载、刷新、恢复和错误
   ├─ rclone.log                 🔧 上传、下载、重试与网络错误
   ├─ operations.jsonl           📊 管理器结构化事件
   └─ local-operations.jsonl     🧾 本地创建、重命名、删除审计
```

| 日志 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| `manager.log` | 管理器是否请求挂载、刷新或退出 | 单个文件一定已上传完成 |
| `rclone.log` | 传输、重试和错误信息 | 没有日志就一定没有问题 |
| `operations.jsonl` | 管理动作及时间 | 资源管理器操作已提交到云端 |
| `local-operations.jsonl` | Windows 观察到创建、重命名、删除 | 远端对象最终成功更新 |

### 🔄 日志轮转

- 管理器与结构化日志达到设定大小后保留有限数量的历史副本。
- rclone 日志按大小、备份数量和保留天数自动轮转，防止长期无限增长。
- `INFO` 级别适合日常运行；`DEBUG` 只适合短时诊断，因为增长更快且会暴露更多文件路径。

### 📏 资源管理器容量

S3 通常没有像本地磁盘一样统一的“桶总容量”接口。`quotaTotalBytes` 只负责给资源管理器提供一个展示用总容量：

- `0`：总容量未知，由挂载端使用默认展示方式；
- 大于 `0`：按指定字节数显示容量条；
- 它不会创建真实服务端配额，也不会阻止超出该数字后的上传。

## 🔐 安全说明

- 🔑 rclone 凭据保存在当前 Windows 用户的 rclone 配置中，不应进入仓库。
- 💾 `VFS full` 会在本机留下已访问或待上传的文件内容，建议启用 BitLocker 或其他设备加密。
- 🧾 日志可能包含文件名、路径和操作时间，公开日志前应再次脱敏。
- 🗑️ 具有写入和删除权限的凭据可能被恶意程序滥用；重要桶应启用版本控制、对象锁或独立备份。
- 🌐 RC 接口仅应监听 `127.0.0.1`，不要暴露到局域网或互联网。
- 🚫 上传期间不要手动删除缓存，也不要强制终止 `rclone.exe`。

## ❓ 常见问题

### 🟢 会自动安装和启动必需组件吗？

不会自动安装 WinFsp 或下载 rclone。用户必须先安装 WinFsp，并将 `rclone.exe` 放到约定目录。完成任务计划配置后，Windows 登录时可以自动静默启动管理器、审计器和所有 `enabled: true` 的挂载。

### 💾 `VFS full` 和“延迟写回 5 秒”是什么意思？

`full` 模式让 Windows 软件更接近使用本地磁盘：文件读写可以经过本机缓存，支持随机读取、修改和延迟上传。文件关闭后，rclone 等待约 5 秒再开始上传，可以合并短时间内的连续自动保存。

这也意味着资源管理器的复制进度结束时，文件可能只是完整写入了本地缓存，尚未完成云端上传。

### 📡 如何判断文件已经上传成功？

应同时检查：

- `Queued` 为 `0`；
- `Uploading` 为 `0`；
- `Failed` 为 `0`；
- `Errors` 为 `0`；
- 状态为 `Connected`，而不是 `Syncing` 或 `Error`。

对特别重要的文件，还可以使用另一个客户端或服务商控制台确认远端对象的大小、时间和校验信息。

### ⚠️ 未同步成功会立即弹 Windows 通知吗？

挂载失败、配置异常或进程错误可以通过托盘状态和日志暴露。瞬时网络重试不应每次都弹窗，否则容易造成通知轰炸。是否对“上传失败”或“队列长期未清空”弹通知，取决于当前管理器版本的通知逻辑；关键文件仍应主动查看状态。

### 📖 大文件如何按需读取？

rclone VFS 会根据应用的读取位置请求对象的相应字节范围，并把已读取数据放入缓存。顺序播放或预览大文件时通常无需先下载完整对象；随机跳转可能触发新的范围请求。某些应用会主动扫描整个文件，因此实际读取量仍取决于应用行为。

### 🧩 分段读取会逐段出现在日志吗？

默认 `INFO` 日志不会逐条记录每个 HTTP Range 请求，通常只记录挂载、重要传输、重试和错误。临时切换为 `DEBUG` 可以看到更多 VFS 与请求细节，但日志增长很快，不适合长期启用。

### 🧾 为什么重命名记录了，但日志不能证明云端成功？

审计器监听的是 Windows 文件系统事件。它能证明“本机观察到了重命名”，但对象存储中的重命名通常实际执行为复制新对象并删除旧对象。最终结果应结合 rclone 日志、队列、错误数和远端检查判断。

### 🔐 本机会留下文件内容或预览吗？

会。`VFS full` 会在 `%LOCALAPPDATA%\S3Drive\buckets\<id>\cache\` 保存已经读取、正在编辑或等待上传的数据。Windows 搜索、缩略图、最近使用记录和具体应用也可能建立自己的预览或临时文件。敏感设备应启用磁盘加密并限制账户访问。

### 🛡️ 时间差会不会带来数据风险？

可能。保存完成到上传完成之间存在缓存和网络传输时间窗；如果此时强制关机、删除缓存、终止 rclone 或磁盘损坏，尚未上传的数据可能丢失。降低风险的方法是等待队列归零、使用正常关机和安全退出，并为云端启用版本控制或独立备份。

### ⚡ 性能主要受什么影响？

空闲时主要消耗来自一个 rclone、管理器和审计器进程。实际速度通常受网络延迟与带宽、S3 Endpoint 性能、本机缓存磁盘、文件数量和应用访问方式影响。大量小文件比同容量的大文件产生更多请求，首次读取比缓存命中更慢。

### ☁️ 是否能像 OneDrive 一样显示逐文件云朵和绿勾？

当前不能。实现逐文件状态通常需要 Windows Cloud Files API、占位文件、同步根注册、图标状态、冲突处理和完整同步引擎。这比盘符挂载复杂得多。本工具提供的是全局托盘状态和队列信息。

## ⚠️ 已知限制

- 这是按需挂载工具，不是 OneDrive 式逐文件同步客户端。
- 资源管理器不会显示逐文件云朵、绿勾或同步进度图标。
- S3 服务端通常不会主动向 Windows 推送目录变化；需要即时查看远端变化时请按 `F5`。
- S3 没有统一的桶容量配额接口，`quotaTotalBytes` 只影响资源管理器容量条显示。
- 对象存储的重命名通常由“复制新对象 + 删除旧对象”实现，大文件重命名可能需要时间和流量。

## ✅ 使用建议

> 🟢 普通浏览和读写：像本地盘一样使用。  
> 🟡 保存大文件后：等待状态恢复为 `Connected`。  
> 🔴 关机、断网或退出前：确认队列和错误均为 `0`，再执行安全退出。
